How Synk works

Synk is a simple identity membership. Members verify once with their face (or backup code), then your product can trust their identity — without storing passwords for them.

Overview

What Synk is

Synk is a standalone membership for proving identity. A person joins Synk, gets approved, and can later check in with their face. Your app or desk only needs to know: this person just verified.

Synk does not decide what happens next. That’s your product’s job — open a door, sign them into an account, check them into an event, or fill a form.

In one line: Synk answers “who is this?” — your product decides “what now?”

Members

For members

  1. Get Synk — request membership with your name, photo, and recovery details at Get Synk.
  2. Get approved — a Synk admin reviews your request. You’ll get a Synk code like SK-XXXX-XXXX.
  3. Sign in — verify with your face (or code + recovery passphrase) at Sign in.
  4. Use the hub — open Member hub for your Synk ID, Community, and business tools.

Tip: keep your recovery passphrase somewhere safe. You’ll need it if face check-in isn’t available.

Businesses

For businesses & products

If you run a product, desk, or door that should trust Synk members, use Synk Business. You’ll get an API key so your system can read a short-lived pass after someone verifies.

  • Account login — Synk confirms the person; your app signs them in.
  • Visitor / front desk — verify who arrived, then your desk flow continues.
  • Access control — verify, then unlock or admit based on your rules.
  • Event check-in — confirm attendance with Synk, then mark them present.
  • Custom — any product that needs a trusted “just verified” signal.

Setup

How to set up your API key

  1. Go to Synk Business and choose Request access.
  2. Tell us your product name, what it does, and a work email. Create a portal password so you can manage settings later.
  3. Wait for approval. When you’re approved, Synk emails your API key (sk_live_…). Copy it immediately — it’s only shown once.
  4. Sign in to the Business portal to:
    • Rotate the key if it’s ever leaked
    • Choose your product type
    • Set what should happen after verify (identity only, autofill, auto-admit, and so on)
    • Pair desk / door devices when your product needs them
  5. In your server, send the key on every pass request as header X-Synk-Key: sk_live_… (never put the key in a public website or mobile app binary).
Keep the key confidential. Treat it like a password. If it is exposed, others can pretend to be your app. Rotate it in the Business portal as soon as you suspect exposure.

Where the key is used

Your backend calls Synk with the API key to consume a pass after a member verifies. Members never see your key. Browsers and kiosks should only talk to your server, which holds the key.

Flow

Verify & passes

Typical integration:

  1. Member opens Synk Sign in (or your screen that launches Synk verify).
  2. Members verify with face recognition (or Synk code and recovery passphrase).
  3. Synk issues a short-lived pass (about 2 minutes). Pass tokens look like skp_….
  4. Your server sends that pass to Synk with your API key. Synk returns the member’s public identity details your app is allowed to see.
  5. Your product continues — unlock, check in, create a session, etc.

Passes expire quickly on purpose. Ask the member to verify again when you need a fresh confirmation.

Developers

API basics

Call the API from your server. You can use either:

  • https://synkid.netlify.app/api/… (recommended — same host as the member site)
  • or the Synk API host your Business portal is connected to

1. Member verifies

Members use the Synk Sign in page, or you deep-link them there. After a successful verify, your product receives a pass token (for example via redirect, QR handoff, or your own bridge).

2. Consume a pass (your server)

POST https://synkid.netlify.app/api/synk-pass
Content-Type: application/json
X-Synk-Key: sk_live_your_key_here

{
  "pass": "skp_..."
}

A successful response looks like { ok, app, profile, pass } — including the member’s name, Synk code, and related fields your app is allowed to see.

Optional headers

  • X-Synk-Key — required API key
  • X-Synk-App or body appSlug — pin the request to a specific app slug when you have more than one

Good practices

  • Call Synk only from a trusted server — never from public front-end code with the live key.
  • Treat passes as single-use unless you have a clear reason not to.
  • If a call fails with unauthorized, check for an expired pass or a rotated key.
  • Store only what you need after verify (often just your own account id linked to their Synk code).

Reference

Glossary

Synk code
A member’s public ID, like SK-XXXX-XXXX. Safe to show; not a password.
Recovery passphrase
Backup secret for logging in without the camera.
Pass
Short-lived proof that someone just verified (skp_…, ~2 minutes).
API key
Secret for your business app (sk_live_…). Used only on your server.
Hub
Member home after login — Synk ID, Community, and shortcuts.
Community
Optional member space for posts and profiles, separate from Business APIs.
Verify action
What your product prefers after Synk confirms identity (confirm only, autofill, auto-admit, wait for staff, etc.).
Business portal
Where you manage API keys, product type, verify action, and devices.
